### Invariants (original)
- Invariants (apply to EVERY task — read first)
    - THE CODE IS THE SOURCE OF TRUTH: every code block in a must-source language (go/mod/yaml/sql/proto/ts/json/…) carries `source: '<repo-root-relative path>'` and passes the snippet-source test (ordered subsequence after comment/blank normalization; `// …` elisions + trailing teaching comments allowed; RATCHET = 0 — an unsourced must-source block FAILS the suite; `<!-- … -->` multi-line elisions do NOT normalize away — spring gotcha). New teaching = write the real implementation first, then quote it; only when no real counterpart exists may a compilable exhibit live in `internal/domain/teaching/` and be quoted. Bash/command/output blocks are exempt. Never relabel a language to dodge the check.
    - Dependency rule: presentation → domain ← data. Handlers never import the data layer; DTOs never leak past repository implementations. Documented exemption: teaching-exhibit handlers may import data/ directly (marked teaching-exception).
    - Thin handlers: parse/validate input → call a use case → map the result to an HTTP response. No business logic in handlers.
    - One error taxonomy end-to-end: typed error values (errors.Is/As-able) → central error-response writer → one consistent HTTP error envelope. Nothing swallowed; every failure logged with a request ID. Panics are for programmer bugs only — recovered by middleware, never used for control flow.
    - DI at the composition root: main.go wires ports (interfaces) to adapters via constructor injection; fake/live wiring switchable at runtime for demos (ScenarioStore, PATCH /api/demo/scenario).
    - Teaching anatomy: each concept section teaches → text → sourced code → ITS live demo INLINE beside it (never queued at page end); every topic closes with a terminal-companion section (text + curl tour, bash blocks). No screen ships with only a CodeBlock.
    - Content depth (family mandate): every topic concept-first with real examples and working demos; target depth = family per-topic median (~3k words, prose floor 2500 test-pinned). SELF-CONTAINED (developer, 2026-10-15, set during the fastapi guide after an audit caught assumed-knowledge gaps — carries family-wide): no programming fundamentals are assumed — prerequisites (language basics incl. control flow/loops/functions/OOP, data structures, formatting) are taught explicitly inside the language topic; every topic is audited for assumed knowledge before it counts as DONE. go-language MUST open with the equivalent of fastapi's python-basics + python-data-and-strings sections.
    - Block-selection standard (developer-mandated family standard, set 2026-10-15 in the fastapi guide, origin ../react/software_developers_guide 2026-09-30): prose stays the DEFAULT; one paragraph per text block (no \n\n stitching); a paragraph enumerating ≥3 parallel points becomes 1–3 framing sentences + a list block (ordered only when sequential; "Lead term — explanation.", 3–8 items, no nesting); tables only where de-facto tabular; sections never mash distinct sub-topics; narrative/argument paragraphs stay prose however long; sweeps are meaning-preserving (wording + numbers verbatim). Author topics THIS way from day one — no retrofit sweep needed.
    - Guide-family consistency: reuse the react guide's design tokens and screen anatomy; the fastapi client is the reference implementation for content-driven screens; theme DARK default, key 'gdg-theme'.
